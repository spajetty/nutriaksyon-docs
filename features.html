FEATURES

Features by role

NutriAksyon is one system with four different front doors. Pick a role below to see what that role is responsible for, the sign-in screen it uses, and every module inside it.

Teacher

CLASS-LEVEL RECORDING · 5 MODULES

The teacher panel is the entry point of the whole system. It is limited to the adviser's own section, so the class list, the weighing sheet, and the reports all stay short and focused.

  • Dashboard, students, growth monitor, reports
  • Own section only
  • Class list import
01 · LOGIN PAGEWhat the role sees before signing in
02 · MODULE WALKTHROUGHEvery section of this role panel, in the order it appears
2.1

Dashboard

A summary of the adviser's own section: how many learners are enrolled, how many qualified for the feeding program, how many were measured, and the attendance of the last feeding session.

  • Class-level counts only
  • Shortcuts to unmeasured learners
  • Latest feeding session status

  • When you click the 'question icon' in Students Card/Table, this shows criteria on how the system evaluates the students if they qualify for the feeding program or not.
2.2

Students

Where the class list is imported. The system reads the uploaded list, computes each learner's BMI and height-for-age status, and automatically marks who qualifies for the feeding program. Qualified learners are listed in the table right after the import.

  • Import a class list in one step
  • Automatic qualification for the feeding program
  • Click a row to open the student profile

  • Import Process

  • Not Included Students - those who have BMI and HFA set as Normal, hence no need to include in feeding sessions.
2.3

Student profile

Opened by clicking any row in the students table. It shows the learner's BMI and HFA analysis for the current measurement, then the trend across every measurement recorded during the feeding program, including previous school years when those records exist.

  • BMI and HFA analysis side by side
  • Trend line across all measurements
  • Previous school years shown when available
2.4

Growth monitor

The weighing sheet. The teacher enters the height and weight of each learner in the class and submits the batch. Once submitted, the measurements update the class table, the student profiles, and the reports.

  • Batch entry for the whole class
  • Validated before saving
  • Feeds every chart and report
2.5

Reports

Class monitoring in one place: who among the class falls under each BMI and HFA status, and whether the class actually attends the scheduled feeding sessions.

  • Nutritional Status Panel

  • Feeding Session Attendance Panel

  • Upon clicking See Dates button

Feeding Coordinator

SCHOOL-WIDE FEEDING PLANNING

The coordinator panel sits between the classroom and the administration. It owns the feeding calendar, reads measurement data across all sections, and turns the school's available crops into meals that can actually be served.

  • Calendar, students, meals, crops, reports
  • All sections
  • Export and crop-based menus
01 · LOGIN PAGEWhat the role sees before signing in
02 · MODULE WALKTHROUGHEvery section of this role panel, in the order it appears
2.1

Dashboard

The coordinator's command view: upcoming sessions across all sections, how much produce is available from the school farm, and which classes still need a scheduled growth monitoring date.

  • School-wide session list
  • Crop availability at a glance
  • Unscheduled classes flagged
2.2

Calendar Scheduling

Where the feeding program is actually run. The coordinator starts a feeding session for a section and schedules the growth monitoring date of each class; that scheduled date is what appears in the teacher's growth monitor menu.

  • Start and close feeding sessions
  • Schedule growth monitoring per class
  • Scheduled dates appear in the teacher panel

  • Start Feeding Session for Today

  • Past Feeding Sessions - cannot save changes to prohibit bias, prompts feeding coors to double-check the attendance before submitting.

  • Schedule Growth Monitoring - displays modal that asks for date, batch, and grade/section to be scheduled upon.

  • View Existing Growth Monitorings - displays modal that shows a table of lists of students weighed-in per grade/section.
2.3

Students Table

A read-only view of every learner in the school. The coordinator does not edit records here; the table is built for filtering, so a section, a BMI status, or an HFA status can be isolated in one click.

  • All learners, all sections
  • Filter by class
  • Filter by BMI and HFA status
2.4

Meal Recommendation

Meals are decided by the coordinator. Crops are chosen here as the basis of the menu, and the list narrows to meals that are both available and realistically cookable with what the school currently has.

  • Batch entry for the whole classSelect the crops to cook with
  • Only feasible meals are listed
  • Menu is saved to the feeding cycle
2.4

Crop inventory

Schools with a farm can keep their harvest here. Every crop recorded is linked automatically to the meal recommendation menu, so unavailable meals disappear from the list, and the system estimates how many servings of a dish the current stock can produce.

  • Track crops and harvest quantities
  • Linked directly to meal recommendation
  • Estimated servings per dish

  • Add Crop/s - select/add new crops and input how much to store in kg

  • See Dates button - display modal to view: [1] Harvest Logs; [2] Usage Logs; [3] Expired Logs
2.5

Reports

The same status and attendance monitoring the teacher sees, but across every class. It also carries the export: the weigh-ins set by the coordinator and all student statuses can be exported and filtered per class or grade level.

  • Nutritional Status Panel

  • Feeding Session Attendance Panel

  • Upon clicking See Dates button

  • Export Center Panel

Admin

ACCOUNTS & SCHOOL SETUP

The admin panel owns the structure of a single school: who is allowed in, which grade levels and sections exist, and which school year is currently active.

  • Whole school
  • Accounts, grade levels, sections, and school year
01 · LOGIN PAGEWhat the role sees before signing in
01.1 · ADMIN SIGN-UP PAGEWhen a new admin wishes to sign up, a token is needed as generated by superadmin.
02 · MODULE WALKTHROUGHEvery section of this role panel, in the order it appears
2.1

Dashboard

A quick read on the school: how many accounts exist per role, how many are still waiting for access, how many sections are active, and which school year the system is currently using.

  • Grade-Level Overview
  • Quick list of teachers and feeding coordinators

  • When you click the 'Resign' button. As shown, I tried relogging-in with previous credentials but it did not work.

2.2

Employee Accounts

The only place teacher and coordinator accounts are created. The admin adds the account, allows or declines their access, and can edit and delete with an option to reassign teachers.

  • Add teacher and coordinator accounts
  • Allow or decline access, and edit or delete accounts
  • Can reassign teachers

2.3

Grade Levels & Sections

Keeps the school structure up to date. Grade levels and sections can be added, renamed, or removed, and every class list and feeding session is attached to one of them.


2.4

School Year

Monitors the school year the system is running on. Starting a new year keeps the previous records readable for trend comparisons, while the drop option clears every record when the school wants a clean start.


SuperAdmin

ADMIN SIGN-UP CONTROL

The SuperAdmin panel exists for one reason: controlling who is allowed to become an admin. It issues the tokens admins must enter while signing up, so nobody can simply register and bypass the system.
